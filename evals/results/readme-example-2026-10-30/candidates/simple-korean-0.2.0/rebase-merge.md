공유 브랜치에는 merge를, 내 로컬 브랜치를 정리할 때는 rebase를 쓰세요.

rebase는 커밋을 새로 써서 히스토리를 한 줄로 만듭니다.
이미 push해서 다른 사람이 받은 커밋에 쓰면 그 사람들의 히스토리와 어긋납니다.
그래서 push 전의 내 작업 브랜치에만 쓰는 편이 안전합니다.

merge는 기존 커밋을 바꾸지 않고 합치는 커밋을 하나 더합니다.
히스토리가 갈래로 남지만, 누가 언제 합쳤는지 그대로 보입니다.
여럿이 함께 쓰는 브랜치에서는 이쪽이 충돌을 덜 일으킵니다.

실무에서 흔한 흐름은 둘을 섞는 방식입니다.
feature 브랜치에서 `git rebase main`으로 최신 main 위에 내 커밋을 올린 뒤, PR을 main에 merge합니다.
팀이 이미 정한 규칙(squash merge, rebase merge 등)이 있으면 그것을 따르세요.
