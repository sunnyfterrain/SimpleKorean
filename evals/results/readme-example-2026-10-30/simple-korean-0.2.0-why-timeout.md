"idempotent"라는 말만으로는 안전하다고 단정할 수 없습니다. 먼저 endpoint가 중복 요청을 실제로 막는지 확인하세요.

idempotent(같은 요청을 여러 번 보내도 결과가 한 번 보낸 것과 같음)라는 뜻입니다.
예를 들어 "주문 123의 상태를 PAID로 바꿔라"는 몇 번을 보내도 결과가 같습니다.
반면 "새 주문을 만들어라"는 보낼 때마다 주문이 하나씩 늘어납니다.

HTTP 표준에서 POST는 idempotent가 아닙니다.
timeout이 나도 서버는 요청을 이미 처리했을 수 있습니다.
이때 재시도하면 주문이 중복 생성될 수 있습니다.

이 endpoint가 안전하려면 보통 `Idempotency-Key` 같은 header를 받아야 합니다.
서버가 같은 key의 요청을 다시 받으면, 새로 만들지 않고 첫 번째 결과를 돌려줍니다.
API 문서에서 이 key 지원 여부를 확인하세요.
지원한다면 배포 스크립트가 재시도할 때 같은 key를 다시 보내는지도 확인하세요.
재시도마다 key를 새로 만들면 중복 방지가 작동하지 않습니다.
