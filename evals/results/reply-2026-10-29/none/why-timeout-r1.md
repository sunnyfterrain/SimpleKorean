**Idempotent**는 "같은 요청을 여러 번 보내도 결과가 한 번 보낸 것과 같다"는 뜻입니다. 예를 들어 같은 주문 요청이 두 번 도착해도 주문이 2개 생기지 않고 1개만 유지됩니다.

**timeout 재시도가 안전한지는 어떻게 idempotent한지에 달려 있습니다.**

- timeout은 요청이 실패했다는 뜻이 아니라 응답을 못 받았다는 뜻입니다. 서버는 이미 주문을 만들었을 수 있습니다.
- POST는 원래 idempotent하지 않습니다. 그래서 "idempotent하다"는 말은 보통 서버가 중복을 막는 장치를 갖고 있다는 뜻입니다. 대표적인 장치는 **Idempotency-Key 헤더**입니다.
- 이 경우 재시도할 때 **첫 시도와 같은 키**를 보내야 합니다. 서버는 이미 처리한 키로 요청이 오면 새로 만들지 않고 이전 결과를 돌려줍니다.

**확인할 것:**
1. API 문서에서 어떤 방식으로 idempotent한지 확인합니다. 키 헤더를 쓰는지, 주문 번호 같은 클라이언트 지정 ID로 중복을 막는지 봅니다.
2. 스크립트가 재시도마다 키를 새로 만들지 않고 **같은 키를 재사용**하는지 확인합니다. 키를 새로 만들면 중복 주문이 생깁니다.
3. 키 없이 "그냥 idempotent"라고만 되어 있다면 확인 없이 믿지 마세요. 주문 생성 후 조회로 중복 여부를 확인하거나 API 담당자에게 물어보는 편이 안전합니다.

요약하면, 같은 키를 재사용하고 서버가 그 키를 지원한다면 안전합니다. 그렇지 않다면 중복 주문이 생길 수 있습니다.
