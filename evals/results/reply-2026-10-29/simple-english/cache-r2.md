옛 가격이 최대 10분 보이는 이유는 Redis에 가격을 10분 TTL(만료 시간)로 저장해 두고, 가격을 바꿀 때 그 캐시 값을 지우지 않기 때문입니다. 읽기 요청은 먼저 Redis를 보고 값이 있으면 데이터베이스를 확인하지 않으므로, 데이터베이스가 새 가격이어도 캐시가 만료될 때까지 옛 값이 나갑니다.

가장 흔한 해결책은 쓰기 시점에 캐시를 무효화하는 것입니다. 데이터베이스 트랜잭션이 커밋된 뒤에 해당 가격의 Redis 키를 `DEL`로 지우면, 다음 읽기가 데이터베이스에서 새 값을 가져와 캐시를 다시 채웁니다. 커밋 전에 지우면 그 사이 다른 요청이 옛 값을 다시 캐시에 넣을 수 있으므로, 반드시 커밋 후에 지워야 합니다. 값을 직접 새 가격으로 덮어쓰는 방식(write-through)도 가능하지만, 동시에 두 번 수정하면 순서가 뒤바뀔 수 있어서 삭제 방식이 더 안전합니다.

TTL은 그대로 두십시오. 삭제 요청이 실패하거나 누락되는 경우를 막아 주는 안전망 역할을 하므로, 가격처럼 민감한 값은 10분보다 짧게(예: 30~60초) 줄이는 것도 좋습니다. 삭제를 여러 서버에서 호출해야 하거나 실패 가능성이 걱정되면, 가격 변경 이벤트를 발행하고 구독자가 키를 지우도록 하거나 실패 시 재시도하는 구조를 추가하십시오.

마지막으로 Redis 말고도 CDN, API 게이트웨이, 브라우저나 앱의 HTTP 캐시(`Cache-Control`)가 가격 응답을 붙잡고 있지 않은지 확인해야 합니다. Redis를 고쳐도 이 계층들이 남아 있으면 옛 가격이 계속 보입니다. 코드를 보여 주시면 어디에서 키를 지워야 하는지 구체적으로 짚어 드리겠습니다.
