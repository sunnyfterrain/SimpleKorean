이 오류는 curl이 서버 인증서를 발급한 기관(CA, 인증서 발급 기관)을 신뢰 목록에서 찾지 못해서 인증서 체인을 끝까지 검증하지 못한다는 뜻입니다. 사내 API는 보통 회사가 직접 운영하는 사설 CA를 쓰거나, 회사 프록시가 HTTPS 트래픽을 가로채서 자체 인증서로 다시 서명하기 때문에 이 오류가 자주 납니다. 드물게는 서버가 중간 인증서(intermediate certificate)를 함께 보내지 않아서 생기기도 합니다.

먼저 어떤 경우인지 확인하려면 다음 명령으로 서버가 보내는 인증서 체인과 발급자를 보면 됩니다. 호스트 이름은 실제 주소로 바꾸십시오.

```
openssl s_client -connect api.example.co.kr:443 -showcerts </dev/null
```

발급자(issuer)가 회사 이름이거나 처음 보는 CA라면 사설 CA 문제입니다. 이 경우 IT 팀이나 사내 위키에서 루트 CA 인증서(PEM 형식 파일)를 받아 아래처럼 지정하면 됩니다.

```
curl --cacert /path/to/company-root-ca.pem https://api.example.co.kr/v1/health
```

매번 옵션을 쓰기 싫다면 환경변수를 `~/.zshrc`에 넣을 수 있습니다.

```
export CURL_CA_BUNDLE=/path/to/company-root-ca.pem
```

다만 이 방법은 기본 CA 목록을 이 파일 하나로 바꿉니다. 외부 사이트도 함께 쓰려면 시스템 CA 번들 뒤에 회사 CA를 이어 붙인 파일을 만들어서 지정하십시오.

macOS 키체인에 회사 CA가 이미 설치되어 있는데도 오류가 난다면, 쓰고 있는 curl이 Homebrew 버전일 가능성이 큽니다. Homebrew curl은 키체인이 아니라 자체 번들을 읽기 때문입니다. `which curl`로 확인하고, 시스템 curl인 `/usr/bin/curl`로 같은 요청을 해 보십시오. 그것이 성공하면 위의 `--cacert` 방법을 쓰면 됩니다.

`curl -k`(검증 끄기)는 원인 파악용으로 한 번 시험해 보는 것까지만 괜찮습니다. 인증 토큰 같은 민감한 값을 보내는 요청에는 쓰지 마십시오. 중간자 공격을 막지 못하기 때문입니다.

서버가 중간 인증서를 빠뜨린 경우라면 클라이언트에서 우회하지 말고, API 담당 팀에 서버 인증서 설정에 전체 체인을 포함해 달라고 요청하는 것이 맞습니다.
