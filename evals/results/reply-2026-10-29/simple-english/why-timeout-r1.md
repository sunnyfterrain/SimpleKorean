재시도가 안전한지는 서버가 중복 요청을 실제로 걸러 주는지에 달려 있고, POST는 기본적으로 그렇지 않으므로 먼저 확인해야 합니다.

idempotent(멱등, 같은 요청을 여러 번 보내도 한 번 보낸 것과 결과가 같음)라는 말은 주문 요청을 두 번 보내도 주문이 하나만 생긴다는 뜻입니다. 타임아웃이 나면 서버가 요청을 처리했는지 알 수 없습니다. 서버가 처리를 끝냈는데 응답만 늦었다면, 재시도가 주문을 한 건 더 만들 수 있습니다.

보통 POST 엔드포인트는 `Idempotency-Key` 같은 헤더로 멱등성을 보장합니다. 클라이언트가 요청마다 고유한 키를 보내고, 서버가 같은 키를 다시 받으면 새로 처리하지 않고 첫 결과를 돌려줍니다. 그러므로 API 문서에서 이 키를 요구하는지 확인하세요. 요구한다면 배포 스크립트가 재시도할 때 최초 요청과 같은 키를 보내야 합니다. 재시도마다 새 키를 만들면 중복 방지가 작동하지 않습니다. 문서에 키 설명이 없다면 "멱등하다"는 말을 그대로 믿지 말고 API 담당자에게 확인하는 것이 좋습니다.
